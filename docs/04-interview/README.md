## ⏱️ 三种备考节奏

### 7 天：面试前急救

| 天数 | 任务 | 最小产出 |
|:---:|:---|:---|
| Day 1 | 精读目标岗位的基础题库 | 20 个 30 秒回答 |
| Day 2 | 选择 2 个岗位专题 | 各画 1 张知识地图 |
| Day 3 | 准备 1 个主项目 | 30 秒、2 分钟、5 分钟三版讲稿 |
| Day 4 | 给主项目做 DFS 追问 | 20 个追问及证据 |
| Day 5 | 系统设计与手撕 | 2 道白板题、2 道代码题 |
| Day 6 | 模拟面试并复盘 | 错题表、含糊数字表、不会题清单 |
| Day 7 | 只补最高风险缺口 | 一页纸速查表 |

### 21 天：形成完整闭环

- 第 1 周：基础题 + 岗位题，建立知识地图。
- 第 2 周：两个项目做证据化复盘，补系统设计和代码。
- 第 3 周：专题深挖、模拟面试、错题重答和简历对齐。

### 42 天：从“准备面试”到“做出作品”

- 前 14 天完成基础与专题知识。
- 中间 14 天补一个可运行、可评测、可复现的项目。
- 最后 14 天完成开源 README、实验报告、简历表达和多轮模拟面试。

## 🧠 一道题怎样才算真正会了

每道核心题至少准备四层：

1. **L1 定义**：30 秒讲清对象、目标和边界。
2. **L2 机制**：能画数据流或控制流，说明关键步骤。
3. **L3 取舍**：知道替代方案、适用条件和成本。
4. **L4 证据**：有指标、消融、失败样本或线上案例支撑。

推荐使用统一回答骨架：

```text
结论 → 问题与约束 → 候选方案 → 选择理由
     → 实现链路 → 指标与实验 → 失败模式 → 下一步
```

不要把工具名当答案。比如“用了 LangGraph”“用了 GRPO”“用了 vLLM”都只是开头；面试官真正会追问的是为什么选、怎样验证、在哪里失败、换约束后怎么改。

## 📦 每个项目都要准备的证据包

- 一张能解释状态、数据、控制和失败分支的架构图。
- 一份可复现的环境、依赖、配置与运行说明。
- 一张 baseline / 主方案 / 消融 / 成本对比表。
- 3 个成功样本、3 个典型失败样本和错误归因。
- 延迟、吞吐、成功率、成本中至少两个可核验指标。
- 个人贡献边界：你决定了什么、实现了什么、验证了什么。
- 一次事故或负结果，以及你如何定位、止损和复盘。

## ✅ 面试前最终自检

- [ ] 我能用一句话说清目标岗位与自己的匹配点。
- [ ] 我有 2 个能讲深的项目，而不是 6 个只能报菜名的项目。
- [ ] 简历上的每个数字都有口径、样本量和对照组。
- [ ] 每个关键选型都准备了“为什么不用另一个方案”。
- [ ] 我能画出主项目的数据流、状态流和异常流。
- [ ] 我准备了真实失败案例，而不是只讲完美结果。
- [ ] 我能区分模型能力、数据能力、Harness 能力和系统能力。
- [ ] 我知道项目从 Demo 走向生产还缺什么。
- [ ] 我不会给未经核验的问题臆造公司来源。
