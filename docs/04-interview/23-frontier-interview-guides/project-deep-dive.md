# 项目深挖：BFS 主线 × DFS 追问

> 项目面试不是复述 README。面试官会用横向覆盖判断项目是否完整，再沿关键节点纵向追问，验证真实性、主导性、判断力和结果可信度。

---

## 📌 本节目标

- 用 BFS 主线补齐项目从背景到复盘的完整链路。
- 用 DFS 算子为每个关键决策生成二、三层追问。
- 给简历数字建立口径、证据和归因。
- 准备 30 秒、2 分钟、5 分钟和 15 分钟四档表达。

## 💡 面试官的隐藏评分表

| 维度 | 面试官在判断什么 | 低分信号 |
|:---|:---|:---|
| 真实性 | 项目、故障和数字是否真实发生 | 只有完美结果，没有细节和失败 |
| 主导性 | 哪些判断和实现由你完成 | 一直说“我们”，说不清自己的决定 |
| 判断力 | 是否比较过方案并理解取舍 | “因为大家都用”“框架比较方便” |
| 技术深度 | 能否从模块下钻到机制与边界 | 只会列工具名，无法画数据 / 状态流 |
| 闭环能力 | 是否定义指标、实验和上线反馈 | 只说“效果不错”，没有口径和基线 |
| 表达效率 | 能否按对方需求控制信息密度 | 背稿、跑题、一次讲完所有细节 |

## 🔍 BFS：项目完整主线

把项目准备成 L0～L10 十一层。BFS 不是要求一次全部讲完，而是确保任何一层被问到都有内容。

### L0. 一句话定位

```text
我为【谁】在【什么场景】解决【什么高成本问题】，负责【个人范围】，最终用【指标】验证了【结果】。
```

避免把技术栈当定位。例如“这是一个 LangGraph + Milvus 项目”没有说明用户、问题和价值。

### L1. 背景与问题

- 用户是谁，原流程是什么？
- 痛点发生在哪一步，频率和损失多大？
- 为什么现在要做？不做会怎样？
- 是真实需求、课程任务还是个人验证？边界要诚实。

### L2. 目标、指标与约束

- 主指标、护栏指标、成本指标分别是什么？
- 数据量、延迟、预算、隐私和上线时间有哪些约束？
- “成功”在项目开始前如何定义？

### L3. 方案空间与选型

至少准备三个候选：最简单 baseline、实际方案、一个更强但没选的方案。

| 方案 | 质量 | 延迟 / 成本 | 工程复杂度 | 风险 | 结论 |
|:---|:---:|:---:|:---:|:---|:---|
| 简单 baseline |  |  |  |  |  |
| 实际方案 |  |  |  |  |  |
| 更复杂方案 |  |  |  |  |  |

### L4. 架构与核心链路

一张架构图至少标出：输入、状态、关键组件、外部依赖、存储、输出、评测、异常分支和人工介入。能沿一条真实请求逐步走完，比画十个方框更有价值。

### L5. 实现细节与个人贡献

- 你写了哪些模块、设计了哪些接口？
- 哪个关键判断是你提出并推动的？
- 最大技术难点卡了多久，最后怎样定位？
- 哪些工作是同事、开源框架或模型完成？

### L6. 协作、排期与风险

- 怎样拆任务、定义依赖和验收？
- 哪个风险最早暴露，怎样改变计划？
- 有冲突时如何用数据或小实验决策？

### L7. 测试与质量

- 单元、集成、端到端和离线评测覆盖什么？
- 测试集如何构建、切分和防泄漏？
- 哪些失败无法自动验证，需要人工或 shadow traffic？

### L8. 上线、监控与止损

- 灰度、回滚、超时、重试、幂等和降级怎么做？
- 看哪些 dashboard 和告警？
- 哪些动作必须人工确认？
- 项目没有上线时，明确说“离线原型”，再说明上线还缺什么。

### L9. 结果与归因

任何数字都要回答：

```text
指标定义 → 数据范围 → 对照组 → 测试环境
        → 结果与波动 → 归因 / 消融 → 业务意义
```

整体上涨不代表每个群体都上涨。准备关键切片、最差组和成本变化。

### L10. 复盘与下一步

- 哪个假设被事实推翻？
- 有什么技术债、适用边界和遗留风险？
- 如果多一周 / 多十倍流量 / 预算减半，优先改什么？
- 如果重做，哪件事不会再做？

## 🧭 DFS：六个通用追问算子

项目主线上的每个关键名词、数字和箭头都可以用下面算子继续下钻。

### 1. WHY-NOT：为什么不是另一个方案

```text
为什么用向量检索，不是 BM25 或混合检索？
为什么用 Agent，不是固定 Workflow？
为什么自己微调，不是换更强模型？
```

准备条件与取舍，而不是贬低替代方案。

### 2. SOURCE：数字从哪里来

对“准确率提升 20%”连续追三层：20% 是相对还是绝对、在哪个数据集、对照是谁、样本量和方差、是否重复实验、谁定义口径。

### 3. BOUNDARY：在哪些条件下失效

每个组件都准备：适用前提、已知失败模式、检测方式、fallback 和不可接受风险。

### 4. SCALE：规模变化会怎样

把数据、QPS、上下文、租户数、工具数或模型尺寸扩大十倍，再讨论容量、延迟、调度、成本和故障域。

### 5. DECOMPOSE：收益怎样归因

用消融、分阶段上线或切片实验拆解：是模型、数据、检索、prompt、cache 还是工程改造带来的提升？

### 6. REDO：重新做会怎样

真正做过项目的人通常能指出错误假设、被低估的成本和更好的顺序。不要回答“会继续优化性能”这种无信息句子。

### 7. OWNER：额外的真实性检查

明确“我决定 / 我实现 / 我验证 / 团队提供 / 框架负责”。诚实缩小贡献范围，比把整个团队成果都说成自己的更可信。

## 🧩 六类节点怎样追问

| 节点 | 第一层 | 第二层 | 第三层 |
|:---|:---|:---|:---|
| 组件 | 它做什么？ | 为什么选它？ | 失败、替代和规模边界？ |
| 连接 | 数据怎样流？ | 格式、时序、重试？ | 一致性、幂等和故障传播？ |
| 数据 | 来自哪里？ | 如何清洗切分？ | 偏差、许可、泄漏和漂移？ |
| 决策 | 选了什么？ | 候选与证据？ | 约束改变后是否仍成立？ |
| 数字 | 指标是多少？ | 口径和基线？ | 方差、显著性和归因？ |
| 事件 | 发生了什么？ | 如何定位止损？ | 哪个机制避免再次发生？ |

## 🎙️ 四档项目讲法

### 30 秒：建立定位

只说用户、问题、个人职责、核心方法和一个结果。不要讲模块细节。

### 2 分钟：讲完闭环

推荐比例：背景 15 秒、目标与约束 20 秒、选型与链路 45 秒、个人贡献 20 秒、指标 15 秒、复盘 5 秒。

### 5 分钟：展示判断力

在 2 分钟版本上增加：方案对比、一个关键实现、一个失败样本、评测口径和上线风险。

### 15 分钟：接受深挖

不要提前背完 15 分钟稿。准备一张项目地图，让面试官选择下钻方向；回答完一个分支后回到主线。

### 单个追问用 PREP

```text
Point：先给结论
Reason：说明约束与理由
Evidence：给实验、数字或故障证据
Point：回扣结论与适用边界
```

## 🎯 高频项目追问

1. 用一句话和两分钟分别介绍项目。
2. 为什么这个问题需要 Agent，而不是 Workflow 或普通 RAG？
3. 三个候选方案是什么，最终为什么这样选？
4. 你个人最关键的技术决定是什么？
5. 项目里最难复现的一个 bug 是什么？
6. 指标怎样定义，测试集怎样来？
7. 这个数字是绝对提升还是相对提升？
8. 哪个消融最能证明核心方案有效？
9. 最典型的三个失败样本是什么？
10. 模型能力和系统能力各贡献多少？
11. 流量、数据或工具数扩大十倍会先坏在哪里？
12. 如果预算减半，保留和删除哪些模块？
13. 项目怎样灰度、监控、降级和回滚？
14. 有哪些隐私、安全或权限风险？
15. 为什么不是直接换更强模型？
16. 团队其他人分别做了什么？
17. 项目没有上线，凭什么说它有效？
18. 哪个结果不符合最初预期？
19. 如果现在重做，顺序和架构会怎样变？
20. 这个项目证明你适合当前岗位的哪三项能力？

## 🧪 三张必须填完的卡片

### 方案对比卡

```markdown
- 问题与硬约束：
- 简单 baseline：
- 候选方案 A / B / C：
- 评估维度：质量 / 延迟 / 成本 / 风险 / 复杂度
- 实际选择与关键证据：
- 什么条件改变后会换方案：
```

### 指标口径卡

```markdown
- 指标名与公式：
- 数据范围、时间与样本量：
- baseline / 对照组：
- 测试环境与模型版本：
- 均值、方差或置信区间：
- 关键切片与最差组：
- 业务意义与限制：
```

### 失败复盘卡

```markdown
- 现象与影响：
- 最初假设：
- 排查顺序与证据：
- 根因：
- 临时止损：
- 永久修复：
- 监控 / 测试怎样防复发：
- 哪个判断以后会改变：
```

## ✅ 一页自检表

- [ ] 一句话中没有只报技术栈。
- [ ] 我能画出输入、状态、数据、异常和人工介入。
- [ ] 每个关键选型都有 baseline 和未选方案。
- [ ] 每个简历数字都有口径卡。
- [ ] 我能区分个人贡献、团队贡献和框架能力。
- [ ] 我准备了三个失败样本和一次完整事故复盘。
- [ ] 我知道规模扩大十倍后第一个瓶颈在哪里。
- [ ] 我能诚实说明未上线、未验证或不确定的部分。
- [ ] 我能根据算法面 / 开发面 / HR 面调整重点。
- [ ] 我练过四档表达，并能在追问后回到主线。
